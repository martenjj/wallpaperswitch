Video Wallpaper Support
=======================

These are the changes made to the Wallpaper Switcher on this branch.
The switcher could set a still image as the wallpaper of a virtual
desktop;  it can now set a video (MP4, MKV, WebM, MOV and other common
formats) just as well, and change from one to the next without the
desktop blanking in between.


What can be done now
--------------------

* A video file can be chosen as the wallpaper for a virtual desktop, in
  exactly the same way as an image and using the same "Set Wallpaper"
  button.  Images and videos can be mixed freely between virtual
  desktops and screens.

* A video is shown in the configuration list as a thumbnail of its
  first frame, generated by a KIO PreviewJob.  This needs a video
  thumbnailer such as "ffmpegthumbs" to be installed;  if there is none
  then a generic video icon is used instead.

* How the wallpaper change is animated is selected in the configuration
  dialogue:  a fade, an immediate change, a slide in any of the four
  directions, or a zoom in or out.  The duration can be set to anything
  between zero and 5 seconds, the default being 350 milliseconds.

* The Plasma "Wallpaper type" never needs to be set by hand.  It is
  selected automatically to suit the wallpaper file chosen.


The wallpaper plugin
--------------------

A Plasma wallpaper plugin, "Image or Video (Wallpaper Switcher)", is
provided in the new "plugin" directory and installed along with the
application.  It is a QML package, so there is nothing to compile.

It exists because of how Plasma changes the wallpaper plugin of a
containment.  ContainmentItem::loadWallpaper() in libplasma creates the
new wallpaper item and deletes the old one immediately, and there is no
transition between one wallpaper plugin and another.  Using the
standard "Image" plugin for images and a separate video plugin for
videos would therefore blank the desktop on every change between the
two sorts of wallpaper, for as long as the new wallpaper took to load,
and that cannot be fixed from outside the plugin.

Showing both sorts of wallpaper in one plugin means that it never has
to be switched.  It keeps two layers, loads the incoming wallpaper into
the hidden one, and only starts the transition once that layer reports
that it has something to show.  Only the layer being changed away from
is animated:  it is the one on top, and the wallpaper appearing from
underneath it is fully loaded, opaque and still throughout.  Animating
both at the same time would let the background show through in the
middle of the transition.

A wallpaper is not released when it is changed away from, so changing
back to it - as when moving between two virtual desktops - starts
immediately.  If a wallpaper cannot be loaded at all, the change is
abandoned and the wallpaper being shown stays, rather than changing to
an empty layer and leaving the desktop blank.

Playing a video needs the QtMultimedia QML module, packaged as
"qml6-module-qtmultimedia" on Kubuntu and similarly elsewhere.


Using the Smart Video Wallpaper Reborn plugin instead
-----------------------------------------------------

Setting "useMediaPlugin" to false in the "[Wallpaper]" group of the
"wallpaperswitchrc" configuration file, or not installing the plugin
above (the BUILD_MEDIA_PLUGIN cmake option), goes back to using the
standard Plasma "Image" plugin for images and

  https://github.com/luisbocanegra/plasma-smart-video-wallpaper-reborn

for videos, with the blanking described above.  In that case the video
plugin keeps its videos in the "VideoUrls" configuration key as a JSON
array, together with the individual settings for each video.  Existing
entries there are retained, with only the video required left enabled,
so that per-video settings made in the plugin's own configuration
dialogue are not lost;  a list in the legacy plain text format is
converted.  The plugin ID can be overridden with the
"videoWallpaperPlugin" setting, for a fork or a compatible successor of
that plugin.


Changes to the application
--------------------------

* WallpaperImageSetter classifies the wallpaper file by its MIME type
  and selects the wallpaper plugin to suit it, changing the plugin of
  the containment if that is necessary.

* The wallpaper for all screens is set by a single Plasma script.  Doing
  each screen by its own script, as before, meant that each screen was
  reconfigured and started to change as its DBus call was processed, so
  with more than one screen the wallpapers visibly changed one after
  another instead of together.  The script writes the configuration for
  all of the screens first and only then reloads it, because reloading
  one containment as soon as it had been written would start that
  screen changing while the next was still being set up.

* Values substituted into the Plasma script are escaped, so that a file
  name containing a quote or a backslash cannot break the script.

* The shared configuration is reparsed before the containment settings
  are examined, because it may have been read earlier in the process
  and both the application and the wallpaper plugins will have changed
  the file since.

* New settings, all in the "[Wallpaper]" group of "wallpaperswitchrc":
  "wallpaperTransition" and "wallpaperTransitionTime" for the
  transition, "useMediaPlugin" to choose the wallpaper plugin
  arrangement, and "videoWallpaperPlugin" as described above.

* libwallpaper additionally links KF6::KIOWidgets, for the thumbnails.
